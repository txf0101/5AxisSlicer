# 五轴软件日常界面验收

## 入口

先核对当前仓库、任务范围、已有修改和候选说明。沿用项目的文档索引、验证环境和最近相关复盘；不要假定某个本机路径或历史候选永久有效。用户只要求审阅时只记录问题；明确授权修复后才改代码。

读 [验收与证据方法](references/daily-ui-checks.md)，按本轮影响选择检查。它区分两个预览入口，记录资源、层注释、缓存、取消状态和布局的复发检查。

## 实际操作

- 原生 Windows 操作使用当前可用的 Computer Use 工具，并先读其技能和 API 文档。脚本、HTTP、Qt 控件测试不能代替实际鼠标操作的证据。
- 操作前记录窗口清单，优先新开自有候选。保留用户窗口和未保存内容；只关闭明确属于本轮且没有需保留内容的窗口。
- 候选必须从交付说明指定的入口启动。核对实际导入位置和候选自带资源；从项目或环境补资源的独立副本只能定位问题，不能证明原包通过。
- 每次关键输入后重新观察。文件对话框先确认文件名框和输入值，再打开；截图被旧窗口遮挡或控件树滞后一帧时，取得稳定观察后再下结论。
- 用户输入保护触发时停止受影响输入，请用户暂停操作；窗口状态读取失败时按工具文档刷新一次，没有新条件就停止重复点击。记录工具错误，继续不依赖桌面输入的工作。
- 本流程默认离线、小输入和短时可取消加载。长计算、机器连接、现场控制和外部发布按本轮授权范围处理。

## 交付

问题按严重程度列出影响、入口、输入、复现步骤和实际结果。修复后核对原始反例、必要回归及受影响真实流程，明确已完成、未验证和工具受阻项。

截图保存到项目稳定教程资产目录或有清单的证据目录，保留来源窗口、操作阶段、语言、真实图像尺寸、输入及关键代码指纹。原图可以直接用于教程；已有模型缺失警告应在图注中解释。用新的独立截图表现修复，不用图像编辑伪造界面。

教程说明用户如何打开、查看、取消和恢复；技术定位与测试次数放入复盘。更新现有 README、教程索引和对应复盘，避免把候选显示能力、整件性能和实机资格混为同一结论。
