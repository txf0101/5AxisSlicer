# 六个工作台开发计划

计划版本：2026-09-10 v1。执行状态以[进度台账](progress_tracker.md)为准；资料依据集中在[参考资料](reference_research.md)。本计划基于现有 Qt UI，按工作台逐个完成几何输入、算法、预览、检查和输出，近期第一个目标是 `pipe2` 管状薄壁分块定向切片。

## 1 本轮确定的目标

用户已选择管状优先，并于 2026-09-12 把 Rotary 调整到 Curve 之后、Freeform 之前。当前完整顺序为 **Tube → Planar → Curve → Rotary → Freeform → Research**。管状需要的截面、偏置、路径语义、运动学和后处理在管状阶段按需建设；这些基础随后复用于其他工作台。每个工作台完成计划列出的操作类型并通过阶段验收后，进入下一个工作台。

本轮交付研究资料、开发计划和可持续更新的台账，不实施切片算法、不安装组件、不运行机床。后续实施按台账选择一个编号任务，完成实现、相关检查和记录更新；共享基础任务也必须服务于当前工作台的具体需求。

用户最新定位为自用、暂无开源计划，取代旧目标文档中的“MIT 开源”定位。现有仓库 `LICENSE` 文件仍含 MIT 文本，本轮不改动许可文件。公开原理、输入输出和独立推导用于自研；引用或集成第三方代码时保留来源与实际许可证。源码改名、翻译或改写不自动消除原有许可条件。

## 4 保留当前 UI 并参考 NX 的落地方式

NX 公开资料用于操作组织、参数含义、生成与验证流程的参考。涉及金属沉积的激光、粉末和熔池参数不直接搬入本项目的挤出式流程。具体界面控件沿用当前 Qt 风格与双语系统。

| NX 可参考的组织方式 | 在现有 UI 的落点 | 本项目需要补充的行为 |
| --- | --- | --- |
| 制造几何、机床环境和操作组织 | Objects 页、Tube 树、Machine 页 | 区分打印体、已有基体、夹具、导引线；每个操作引用稳定对象 |
| 工序选择与参数编辑 | 六入口和对应操作属性区 | 显式选择上述 20 种操作；不支持时显示原因，禁止无效 Generate |
| 工序生成和关联更新 | 当前主操作区与后台任务 | Generate、Cancel、重新生成；输入变化标记依赖结果 Dirty，保留上次有效结果并标明已过期 |
| 分块、层和路径检查 | 中部 Viewer 与 Preview 页 | 区段、切层、轮廓、空移、姿态、选中段属性与问题定位 |
| IPW 和机床仿真 | Checks 页和分阶段回放 | 逐层沉积几何、喷嘴/夹具/已打印体检查、轴位驱动回放 |
| Post 与制造输出 | 输出动作和成果页 | 输出命名、控制器语义、完整报告和 G-code 回读核对 |

项目继续只有一个当前打印零件，可以包含多个 solid；一个零件允许多个顺序 Operation，例如底座打印和管体打印。多零件排版不进入本版。首个 Tube 闭环先保持单 Setup，待多工序确有需要时扩展当前“一条 Tube Operation”的限制，迁移旧工程并验证 YAML 与项目主档的一致性。

每个参数有单位、取值范围、默认值、悬停解释和受影响的生成阶段。GUI、受限脚本和 HTTP 使用相同的领域命令，脚本仍不执行任意 Python。操作名称、状态和错误提示保持中英对应；界面不显示内部缓存和调试实现细节。

## 5 共享算法接口及最小建设顺序

先定义数据边界，再以 Tube 需求逐项实现，避免先改造整个应用壳。

```text
Setup + OperationDefinition + GeometryReferences
  → GeometryAnalysis
  → SlicePlan（区段、构建方向、层面、误差）
  → Toolpath（位置、法向、喷嘴轴、沉积与空移语义）
  → MachineAxisTrajectory（轴位、速度与转位）
  → ValidationReport
  → Postprocessor → G-code 回读验证
```

- `ToolpathPoint` 使用工件构建坐标，内部长度 mm、角度 rad；对外角度单位显式声明。包含 position、surface_normal、tangent、nozzle_axis、feedrate、bead_width、layer_height、operation_id、stage_id、layer_id、region_id、point_type、extrusion_role 和问题引用。
- 路径与事件分开表达。Retract、Prime、Dwell 不强制伪装成带长度的线段；沉积量以材料体积作为中间量，后处理按送丝直径、流量系数和绝对/相对 E 模式转换。进给速度与轴速度的单位分别定义。
- 每个结果记录输入几何哈希、参数语义哈希、算法版本、资源快照、生成时间和检查状态。无效数值、空路径、断链、过期结果不得进入可导出状态。
- 生成结果先接入现有 Viewer 适配器，再输出 G-code；不能先拼 G-code 再解析回来充当唯一算法结果。
- 复用当前机器轴链与正运动学，增加逆运动学、解支选择、角度展开、速度/加速度约束和不可达报告。XYZAC 与 XYZAB 分别使用注册模型和测试，不替换字母来声称等价。
- 几何算法不进入 `ui.py`。建议逐步增加 `manufacturing/toolpath.py`、`algorithms/tube/`、`algorithms/planar/`、`kinematics/`、`validation/`、`postprocessing/` 等职责模块；实际路径在对应任务开始时结合当前代码确定，不预先创建空框架。

## 6 管状第一个完整流程

### 6.1 输入与角色

首个案例使用现有 `example/pipe2/弯管新.stp` 和坐标示例工程。管体与圆盘底座分别确定角色：第一轮算法默认只生成管体，底座作为已有构建基体；如果需要打印底座，后续单独生成并编排底座操作。当前 Part 可含两个 solid，不代表两个 solid 都是待识别管体。

历史分析认为该管为外半径 16 mm、内半径 15 mm、圆弧中心半径 35 mm，弯曲角约 70.513331°。这些数值来自旧复盘，T01/T02 必须从当前 STEP 重新测量，不作为本轮重算结果。

管特征先支持圆柱、环面和圆形端口。用户选管体、入口、出口并确定流向；系统显示识别出的中心线、截面、壁厚与分析问题。同时保留“用户指定中心线”的输入模式。STEP 接缝 edge、端口圆边不能直接冒充中心线。分叉、歧义或超出首版范围时明确拒绝，允许回到人工几何定义。

### 6.2 分块和切层

以中心线方向变化、最大楔角和允许道高误差共同控制分块。楔角是候选分段参数，最终要以生成层面与实际几何的误差核查决定是否接受。每个区段输出固定构建方向、覆盖区间、层面与归属规则。

重点处理分块交界处的重叠、空隙、微小尾层、非闭合截交、多轮廓与内外环方向。层面间距、挤出道高、道宽和曲面距离分别定义，不能用一个数值互相替代。切片预览必须先于打印路径预览，支持定位某一段或某一层的失败。

### 6.3 薄壁路径和拼接

从每层闭合截面生成单道或多道薄壁中心路径，明确边界偏置与壁厚处理方式。接缝规则、路径方向、短段过滤、挤出量、回抽、抬升和重新 prime 使用结构化状态。分块之间输出停止挤出、安全退离、转位、接近和恢复沉积的独立阶段。

外部软件切片后手工拼接的例子用于识别工序顺序和衔接意图。算法自行生成连接段；最终生成结果须保存连接段的来源与规则，不能将人工拼接文件当作可重生成定义。

### 6.4 两次交付门槛

**T08 是 Indexed 最小完整流程验收**：从 STEP 和 Setup 出发，在 UI 中生成、逐层检查、求轴位、后处理、回读，修改参数后重新生成，保存并重开。只有路径线可看不算通过。

**T12 是整个 Tube 工作台验收**：Indexed、Buildup、Continuous 三种操作全部达到规定范围，包含多工序底座编排、错误样例、保存重开、帮助说明和实际生成结果展示。T08 通过后仍继续补齐 Tube，不立即转到其他工作台。

## 7 各阶段的验收规则

### 7.1 统一软件完成条件

1. 指定支持范围的正常样例能从几何输入生成路径，边界和失败样例能给出可定位错误。
2. UI 参数真实改变结果；取消、失败、旧结果过期、撤销和重开行为正确。当前双语界面与两个 Viewer 后端做相关回归。
3. 几何误差、层间距、路径间距、挤出量和材料参数采用不同指标；阈值在相应任务执行前写入案例配置及复盘。
4. 用独立解析真值或独立测量核对算法，不能只让测试重复实现。建议解析几何夹具初始位置容差 0.01 mm、姿态往返误差 0.01°；这是待在 T01 验证的数值测试起点，不代表设备制造精度。实际道高、道宽和安全间隙阈值来自对应材料与设备配置。
5. 路径点与轴位经 FK 回算对照。连续轨迹检查整个转位/运动区间；碰撞采样步长有误差上界或采用保守包络，单点不碰撞不能证明整个运动安全。
6. 检查喷嘴与机床、基板、夹具及已打印体的相交；沉积接触区按明确规则处理，避免把正常喷嘴接近当作碰撞。Error 阻止输出，Warning 随报告导出；参考机型输出明确标记为仿真用途。
7. 输出 `main.gcode`、`toolpath.json`、`machine_axes.csv`、`warnings.json`、`preview.json` 和来源/参数清单。G-code 按目标控制器语义回读，核对顺序、姿态、范围、挤出与停止状态。
8. 运行与修改相称的领域测试、UI 冒烟和项目回归。阶段结束运行 `scripts/check_quality.py`、完整 pytest、构建和包检查；保存命令、环境、结果与产物路径。
9. 每个工作台阶段验收前完成对应图文使用手册，至少包含入口、参数、正常流程、错误恢复、三维结果、导出与保存重开；截图来自当前版本真实界面。手册要求和清单见[使用手册索引](../guides/README.md)。

工作台软件完成与真实设备验证分别记录。暂无真实机床参数时可完成注册参考机型的离线软件验收，实机状态保持“未验证”；不上机自动执行，也不把参考机型的通过报告解释为真实设备安全认证。若参数缺失影响算法本身，则阻塞对应任务并记录条件。

### 7.2 各工作台重点

| 工作台 | 几何与运动重点 | 阶段验收补充 |
| --- | --- | --- |
| Tube | 中心线、楔块接缝、闭环、固定与连续姿态 | 分块覆盖无遗漏；连续模式在直线/低曲率/反曲附近不翻转；三操作均可生成和回读 |
| Planar | 孔洞、岛屿、薄壁、连续 Z | 轮廓不越界；填充覆盖有可测残余；螺旋不把多岛静默连成沉积线 |
| Curve | 拓扑顺序、弧长、横向偏置 | 反向 edge 一致；无关联法向时要求显式方向；自交或偏置失效可定位 |
| Freeform | UV 度量、修剪、接缝、法向偏置 | 用三维距离验证道间距；多面法向连续；偏置自交/投影多解报告明确 |
| Rotary | 回转轴、角度周期、螺距、速度 | 0/360° 接缝无异常；回转轴速率满足约束；非零回转中心和刀长参与求解 |
| Research | 场来源、等值层奇异、算法基线 | 每方法至少正常/失败案例、参数记录、可复算报告；有负结果也如实留存 |

研究工作台的强度效果须有力学计算或实验依据。只完成方向场与路径对齐时报告“方向一致性”，不写成强度提高；少支撑代理指标降低也不等同实际打印成功。

## 8 样例来源与比较方法

## 9 执行与更新方式

每轮从[台账主表](progress_tracker.md#主表)取一个依赖已满足的任务。开始时读取当前文件并核对时间戳，更新状态；结束时写入实际代码/报告/测试证据、下一步和日期。已有授权范围内的常规实现及本地验证继续执行，无须逐条重新审批；不推断本轮计划编制已授权实机操作或对外发布。

若任务需要细分，新增同前缀子编号并保留父行和范围变化记录，不删除旧证据。研究假设、工程实现、回归通过、工作台完成分别表达。最终进度按验收通过的任务计数，任务数不代表工时，不填缺乏依据的百分比或日期承诺。

首轮实施应从 **A01 管状算法基线与契约**开始，随后完成 A02 样例来源登记和 A03 通用路径契约，再进入 T01。开发分支使用 `codex/` 前缀；本轮仅更新规划文件，不创建算法实现分支。
