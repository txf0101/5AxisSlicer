# 2026-07-03 预览区主选边线复盘

## 调整目标

本轮把选择入口按对象密度重新分工。块体数量少，用户可以在右侧列表逐项点选并观察高亮；边线数量大，空间位置和模型表面关系更强，保留在左侧预览区点选更接近真实判断过程。改动后，右侧列表、左侧高亮、HTTP 状态和项目保存仍使用同一份 `SelectionState`，避免出现列表选中和保存结果不一致的状态。

## 取舍判断

- 预览区固定为 edge picking，body actor 不再响应预览区点选。这个边界让三维视图承担最需要空间判断的工作，减少模式切换带来的误点。
- body 选择保留在右侧列表和 `/selection/set`。这条路径更稳定，也适合脚本批量设置。
- `/selection/mode` 继续保留 `edge` 入口，传入 `body` 时返回明确错误。旧自动化脚本能快速定位迁移方向，迁移方式是改用 `/selection/set` 写入 `body_ids`。

## 可复用方法

1. 交互入口按对象规模拆分：少量对象走列表，高密度拓扑对象走空间视图。
2. 渲染层承担最终约束：Viewer 层拒绝 body picking，界面层隐藏切换入口，避免多个入口互相绕开。
3. 验证同时覆盖状态和视觉属性：检查 `SelectionState`、actor pickable、颜色、线宽和列表勾选，比单纯看 HTTP 返回更可靠。
4. 本轮使用 `example/扇叶/风扇扇叶.STEP` 做真实模型验证，加载结果为 4 个 body、348 条 edge；右侧列表可写入 body 选择，预览区可写入 edge 选择，`/selection/mode` 传入 `body` 会返回明确错误。

## 后续观察

- 大模型 edge 列表仍可能很长，后续可加 body 过滤或 edge 搜索。
- 若后续需要恢复 body 预览点选，应作为独立模式设计，不能只把旧快捷键加回来。
