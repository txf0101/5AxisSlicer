# 多对话工作台提示词编制复盘

## 解决的问题

本轮把后续工作台开发整理为六份可直接复制的 Codex 启动提示词。每份提示词以完整工作台和当前版本验收为终点，并把图文使用说明、真实截图、产品状态、六件套、回读、保存重开、证据和 Git 交接纳入完成条件。

## 判断与取舍

- 沿用唯一台账的依赖顺序，没有因多对话开发自行解除 P07、Curve、Rotary、Freeform、Research 和整体验收之间的阶段依赖。
- 多 Agent 用于互不写同一文件的盘点、真值、资料、测试矩阵和文档审查；共享接口、Qt/VTK、完整回归和阶段关闭保留给各任务主 Agent。
- 当前 `main` 存在大量未提交 Planar/P07 修改，因此提示词要求先收尾并提交 P07，再从干净基线建立后续 worktree。
- 本版计数明确为 21 种制造操作，即原计划 20 种加 1 个 Planar Support；Lines/Grid 是同一支撑操作的两种 pattern，Region 是预览/分析节点。最终集成提示词要求建立 21×2＝42 个操作—机型组合矩阵，并统一更新计划、台账、验收矩阵、交付清单、示例索引和总手册。
- 提示词允许本地实施、测试、文档和提交，不自动扩大到推送、发布、付费外部计算、真实机床或现场试切。

## 使用的 Skills 与依据

- `five-axis-workbench-development`：确定领域链、状态、验证、图文手册、证据、台账和阶段关闭要求。
- OpenAI Docs 的 Codex 提示词指导：采用结果优先、明确上下文/边界、写清验证方式和可直接使用的交付格式。官方页面：[Prompting](https://developers.openai.com/codex/prompting)。

本轮只编写规划文档，没有进入代码测试或工作台阶段验收，因此没有调用 `five-axis-slicer-validation`，也没有运行项目测试。

## 局限

提示词不会让存在硬依赖的工作台自动具备并行合并条件。后续任务仍需从实际已验收并合入的干净提交创建 worktree。分支名可以调整，但起点提交、依赖、证据和完成判据不能因改名而省略。
