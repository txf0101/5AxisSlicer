# 2026-07-07 五轴 G-code 体积路径与进度预览复盘

## 本轮目标

本轮围绕叶轮 G-code 预览的可读性继续推进。前一版已经把机床 XYZ 按 `P_part = Rz(-C) * Rx(-A) * P_machine` 反算到工件坐标，本轮重点放在两个问题：路径从 VTK 折线升级为有宽高的挤出道；五轴路径增加按 G-code 执行顺序推进的横向进度，用来补足单纯 Z 层滑条的表达范围。

用户给出的视觉基准来自 Bambu Lab / PrusaSlicer 的切片预览：成型道有体积，Feature Type 用颜色区分，拖动进度后能看出当前步骤。五轴样例含 A/C 旋转，Z 方向层滑条仍保留，但不再承担完整的进度语义。

## 实现记录

- `gcode_preview.py` 新增 `;HEIGHT:` 解析，路径段保存 `step_index`、`height`，宽度缺省为 `0.4 mm`，高度缺省为 `0.2 mm`。
- 新增全量 `GCodeTimelineStep`，纯 E 回抽和 prime 进入进度读数，不生成 VTK 几何；空间路径段仍保持 MATLAB 口径统计。
- `summary()` 增加 `timeline_step_count`、`height_range`、`progress_domain = layer_filtered_gcode_order`，缓存版本升级为 `gcode-preview-v4-timeline-beads`。
- `viewer.py` 新增扁椭圆挤出道网格。截面方向由路径切向和五轴喷嘴方向共同确定，当前步骤用白色覆盖，未来步骤可淡显。
- 交互和百万段样例采用自动分级：静态显示实体道，拖动进度或旋转视图时降到轻量线模式，避免本地 UI 被重渲染拖住。
- `ui.py` 增加横向 G-code 进度条和 `/preview/progress` 接口。底部视图区进度条保留；由于 Windows 下 VTK 原生窗口会覆盖普通 Qt 控件，右侧 Preview 页也放置同步进度条，保证功能可操作。
- 自动化桥等待从 30 秒调到 120 秒，避免实体路径大场景的合法重绘被 HTTP 层误判为失败。

## 质量判断

本轮没有把“体积线”做成单纯加粗的 VTK line。实际实现保留了宽高、喷嘴方向、路径切向和 Feature Type 颜色四类信息，形成后续五轴姿态诊断能复用的几何入口。扁椭圆扫掠没有做段间布尔融合，拐角处允许轻微搭接；这符合当前预览阶段的目标，也控制了百万段文件的计算成本。

进度模型和几何模型分开存放，是这轮较关键的结构选择。timeline 承担真实执行顺序，路径段承担可绘制几何；这样回抽、prime、空走、A/C 姿态变化都能解释，VTK 又不会被不该画线的动作污染。这个结构后续可继续接入时间估算、耗材统计、姿态突变标记和轴限位检查。

右侧同步进度条属于工程现实下的可用性修正。计划中的视图区底部控件保留，但 Windows 的 VTK 原生窗口层级会遮住普通 Qt 控件；把同一进度状态放进 Preview 页，牺牲了一点布局理想形态，换来了稳定可操作的界面。这个判断比坚持不可见控件更接近桌面工程软件的交付标准。

## 后续建议

- 若要真正绘制叶轮全部 1,011,023 个空间段，需要取消当前大文件几何抽样；代价是内存、缓存和 VTK 构网时间会显著上升。当前策略是全量 timeline 加抽样几何，适合交互预览。
- 可在进度条上增加层变化、Feature Type 变化和 A/C 姿态突变标记，当前数据结构已能支撑。
- 可增加“实体 / 轻量线 / 当前窗口”三档显式切换，让用户在截图质量和交互速度之间主动选择。
