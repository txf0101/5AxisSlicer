## 1 任务边界与现场问题

本轮处理两个直接影响使用的问题：三维预览的鼠标手感与 Bambu Studio 差异较大；STEP 已经载入后，用户无法从普通操作会话判断坐标定义位于何处。坐标算法、项目 v2 格式和 Tube Setup 领域模型保持原边界，中心线、分块、切层、路径生成、逆运动学及 NC 输出未进入本轮范围。

修改前再次只读核对 `圭臬/开发目标文档.docx`。文件大小为 492214 字节，修改时间为 2026-07-06 13:45:16.409 +08:00，与 2026-07-24 实施复盘记录一致。本轮没有改写该文档。

行业没有可验证的单一“大厂标准”。本轮采用公开源码、状态机测试、双渲染后端一致性、静态类型、复杂度预算、真实桌面点击和独立审查组成可复现证据，避免用组织名称代替工程判断。

## 2 鼠标交互依据与实现

交互规则核对到 Bambu Studio 固定提交 [`12f17b06f4f537f9c03162d08bb70cf733c42839`](https://github.com/bambulab/BambuStudio/tree/12f17b06f4f537f9c03162d08bb70cf733c42839)：

- [左键旋转、中键或右键平移](https://github.com/bambulab/BambuStudio/blob/12f17b06f4f537f9c03162d08bb70cf733c42839/src/slic3r/GUI/GLCanvas3D.cpp#L5799-L5895)；
- [空白左键释放时清除选择](https://github.com/bambulab/BambuStudio/blob/12f17b06f4f537f9c03162d08bb70cf733c42839/src/slic3r/GUI/GLCanvas3D.cpp#L5904-L5946)；
- [保留滚轮增量并围绕鼠标位置缩放](https://github.com/bambulab/BambuStudio/blob/12f17b06f4f537f9c03162d08bb70cf733c42839/src/slic3r/GUI/GLCanvas3D.cpp#L5146-L5168)。

`viewer_interaction.py` 保存一套按钮和拖动状态机，OpenGL 与 VTK 各自提供相机数学适配器。左键短按提交拾取，越过系统拖动阈值后进入旋转；中键和右键拖动进入屏幕平面平移；滚轮缩放保持光标对应的目标平面点。窗口失焦、隐藏、离开或按钮状态丢失会取消手势并恢复预览质量。

独立审查复现了一个多键边界：左键拖动期间按下右键会覆盖活动手势，结束回调无法执行。状态机现忽略活动手势期间的附加按键，错误顺序释放也不会清除原手势。回归用例覆盖该序列，避免 OpenGL 或 VTK 长期停留在交互简化预览。

本轮没有加入对象拖动、Gizmo、框选和右键菜单。这些行为需要对象变换、命令撤销与上下文菜单合同，不能由相机手势顺带承担。

## 3 坐标入口与中文界面

普通操作会话在 STEP 有效时显示蓝色按钮“进入管状设置（定义坐标）”。入口复用现有 `CadModel` 和 `TubeSetupController`，切换页面时不再读取 STEP。管状树会定位到可编辑的坐标前置节点；用户先前选中过“项目”“模型”或操作容器时，重复进入也会回到首个未完成节点，不再显示空编辑器。

Tube 文案和工作台目录从历史 Qt 大类移到 `tube_ui_text.py` 与 `workbenches.py`。静态控件采用声明式文案绑定，`TubeSetupPage` 回落到上下文预算以内。Part 下拉框以中文显示“零件”“忽略”“未分配”，数据层继续保存 `part`、`ignore`、`unassigned`。语言切换只更新显示文本，尚未确认的角色选择保持不变。

真实桌面验收使用 `pipe2` 的两个 solid。点击坐标入口后，主窗口、Tube Viewer 和 controller 指向同一模型对象；创建操作后按钮禁用；Part 页面显示两个中文角色下拉框。五张界面截图保存于 `docs/guides/assets/tube_coordinate_setup/`，中文指南位于 `docs/guides/tube_coordinate_setup_zh.md`。截图生成时发现 Windows DPI 虚拟化会造成裁剪偏差，最终捕获进程先声明 DPI 感知，再按真实窗口矩形保存图像。

## 4 代码质量判断

共享手势层只处理事件分流和生命周期，相机坐标计算留在后端适配器，拾取仍由各 Viewer 按自身数据结构完成。这个边界减少 OpenGL 与 VTK 的重复事件代码，也保留各自的投影、像素比例和世界坐标换算。

注释集中解释 Qt 与 VTK 的 Y 轴原点差异、拾取为何在释放时提交，以及交互预览的结束边界。可由类型和函数名直接表达的流程没有重复注释。新增状态使用小型数据类与字面量类型，未向 `ui.py` 或 `tube_ui.py` 填入新的工作台分支表。

终检中的入口重入、多键手势和语言切换选择丢失均来自行为审查，修复落在共享状态边界；没有为单张截图或单个样例写特殊条件。静态门禁结果如下：

## 6 可复用沉淀与后续边界

本轮形成三项可复用资产：带固定提交的桌面三维交互行为矩阵；不依赖渲染后端的指针状态机；从通用会话携带权威模型进入专业工作台的入口模式。Planar、Rotary 与 Freeform 后续接入独立 Setup 时，可以复用入口和文案绑定方式，并继续共享相机手势。

差异化价值来自证据链的完整性：公开源码给出行为来源，纯状态机测试封住事件顺序，双后端数学测试检查画面一致性，真实截图验证用户能找到入口，独立审查再追踪失败生命周期。单纯复刻按钮位置无法覆盖这些层次。

下一阶段若加入对象拖动或 Gizmo，应另建对象编辑命令与撤销事务；若其他工作台接入坐标编辑器，应由共同的 Setup 能力声明入口，避免复制 Tube 页面。真实机床标定、喷嘴碰撞数据和工艺参数仍需物理测量来源，参考模板不能替代设备数据。
